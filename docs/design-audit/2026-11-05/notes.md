# Product Design 复核 · 2026-11-05

范围：研究者从前沿动态选择具体进展、查看改动与证据。使用本轮新截图，未沿用旧图；未测试原生 iPhone。

1. 桌面入口（01-desktop-start.png）：通过。日期与具体增量在首屏，左列已有作者报告的指标；右侧默认展开方法改变与对照。风险：右侧证据详情需要继续滚动，“已了解”位于内容末端，快速处理成本偏高。建议把处理动作固定在详情工具区，并保留证据来源层级。无障碍风险：选中项目前主要依赖颜色，需补充语义状态并验证键盘焦点。仅凭截图不能判断完整读屏体验。

2. 手机入口（02-mobile-start.png）：通过，需小修。375px 无横向溢出，首屏可读 RAFT 和异步策略的具体改动与关键证据。书签触控高度实测 44px；单行标题按钮仅约 28px，建议扩至至少 44px，并明确书签对应的论文名称。顶部工具占用一定空间，仍能在首屏看到具体进展。截图不能证明 VoiceOver、字级放大与真机键盘体验。

3. 手机详情（03-mobile-detail.png）：通过。点击标题打开有关闭入口的对话框；新改动、对照和作者证据按顺序出现，核对层级明确。风险：处理动作在正文末尾，后续适合与精读任务入口一起设计为固定工具区；当前未声称存在自动精读队列。此次没有向 GPT API 发送论文，也没有创建定时任务。截图可见对话框布局正常，但不足以证明焦点锁定与键盘返回行为。

修复复核（04-mobile-fixed.png）：手机单行标题按钮实测已为 44px，书签的可访问名称包含对应进展标题。桌面以键盘 Enter 切换到 ARP 后，焦点保留在该条标题，aria-current 为 true，并关联到展开详情区域。原有 12 项网页逻辑回归通过。以上是本轮可确认的改进，不代表完整 WCAG 或原生真机验收。

后续优先项：在精读队列实现时，统一设计固定的任务/处理操作区。自动精读目前为设计方案，尚未创建定时任务或调用 GPT API。用户的托管与无密钥约束、执行提示与队列状态见 ../../automatic-reading.md。
