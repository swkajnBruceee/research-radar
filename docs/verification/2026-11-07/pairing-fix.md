# 扫码退出后无反馈：修复与安装

用户实测表现是相机退出后没有提示或连接。原实现会在识别时停止扫描、调用结果并关闭相机，但成功分支仅填入地址，没有反馈，也不发起连接；错误交给父层提示，嵌套弹窗中不易看到。公网访问改造后默认二维码又改为网页根地址，早期 App 仅接受 `embodiedradar://connect`，形成兼容风险。

本次修复：

- Mac 配对页默认展示兼容原版 App 的邀请二维码；明确区分“App 配对码”和“Safari 网页码”，分别给出步骤。
- 原生 App 统一解析两类二维码。扫码结果在扫描弹窗关闭后处理，连接页只初始化一次，避免返回时重新填充初始状态。
- 成功显示“已识别研究台”和下一步按钮，提醒输入访问码、点击连接；失败由连接页直接提示。二维码不含访问码，不在扫描后自动提交凭据。
- 扫描器补充更新与点击回调、启动错误和运行中不可用的反馈，不再静默忽略扫描异常。
- 构建版本更新为 1.0（2）。

验证：Swift 核心测试 9 项通过，包含两类码、凭据/查询参数和异常地址拒绝；JavaScript 28 项通过，包含 App 邀请格式、Safari 根地址、通道变更与失效回退。已使用现有开发团队完成 Debug 真机签名构建。

已通过 devicectl 在当前连接的 iPhone 15 Pro Max 安装修复版，随后查询确认为 1.0、build 2，并成功携带当前 App 邀请链接启动。安装使用原 Bundle ID，没有卸载或清空应用数据。

浏览器已确认配对页默认选中“App 配对码”，步骤明确提示“保存并连接”，截图见 [修复后配对页](app-pairing-fix.jpg)。真实相机再次扫码、填写访问码与连接结果仍由用户在手机上验证，未将启动成功等同于扫码流程验收。
