# 为什么重要研究没有及时呈现：机制检查

2026-11-08；范围为真实定时任务、候选数据库、筛选/领取协议、全文发布门槛、本机和公网内容接口、iOS同步实现。没有改变个人笔记、已读、收藏、关注方向或选题，没有调用付费模型API或创建其他自动化。

## 结论

问题确实出在机制。上一轮补收SuperMimic、增加标签和历史回扫，只解决了部分问题。原有系统没有形成持续、可追踪的候选比较；真实定时提示与项目流程不一致；版本识别误伤已读论文；重要性分档仍缺少跨论文校准。采集成功不等于重要研究已经被识别、精读并送到手机。

## 已核实的缺口

1. **发现范围不足。** SuperMimic在上一轮检查时不在数据库，2026-11-07T09:20:23Z才补入；原有近期45篇窗口没有历史覆盖。现已具有最近100篇、每轮200篇历史回扫及关键论文追踪，但搜索仍限定带关键词的cs.RO；CoRL/OpenReview入口未启用。关键追踪清单只有SuperMimic，不能代替独立发现机制。行业博客、模型和代码发布虽然有采集器，当前全文领取与前沿发布链主要只处理arXiv论文，不能声称全行业覆盖。

2. **初筛没有被强制执行。** 首次检查有1,168个可处理候选，全库只有10条初筛记录，全部为level 2。专用任务最近三轮都有shortlist命令，但仅给最终选中论文记录最高等级，没有记录其余候选的常规或较低等级判断。最新一轮screen因引文不匹配失败后，claim仍领取了按日期排在前面的轮式导航整合论文；随后代理释放并修正。这证明失败会静默退回日期排序，并非纯理论风险。

3. **实际任务仍写“优先最新论文”。** docs/reading-queue/agent-run.md已经要求初筛，但真实automation提示与docs/automatic-reading.md仍保留旧指令。目标确实是专用会话，任务未停止；问题是指令和执行约束，而非没有运行。

4. **已读论文被元数据差异误隐藏。** 有29份独立全文报告，旧部署只有21篇可发布。8份文档的旧签名可以由“未带v1的abs链接 + RSS日期2026-11-06”逐项重现；其缓存原文与当前API来源都明确指向同一个v1。旧代码把链接和日期差异当作内容版本变化。详见version-mismatches.json。

5. **分档内仍会发生优先级失真。** 真实公网排序中，RL接口验证与VFlash同为priority，日期较新，排在SuperMimic之前；SuperMimic是第3，不能再宣称固定排首位。结构化引文校验只能验证出处与字段，不能证明重要性判断合理。逐篇产生最高等级、缺少跨论文比较，仍可能让范围较窄的工作压过更广泛的路线变化。此项尚未完成校准，不因增加一个标签就视为解决。

6. **处理能力与送达均有边界。** 保留每3小时完整精读一篇，即理想情况下每天8篇。修复后仍有1,143个未初筛候选；按每轮24篇清理现有积压至少需48轮，约6天，未计新增与中断。iOS依赖配置的服务器地址和前台重连；临时公网URL改变后旧地址不能自动恢复；手机可能继续显示缓存。服务端下载成功不构成真机收件证明。

## 本轮已实施并部署

- shortlist持久保存最多24篇的版本绑定批次；中断接续本批。仅未评估候选占用名额，兼顾最新、最早等待及研究方向。已有优先项另列，不再占满初筛名额。摘要不再截断到1600字符。
- 本批逐篇记录0/1/2、理由及逐字原文后才能领取；未完成、引文写入失败或指定未评估候选均拒绝领取。通过后在全部已初筛候选中按重要性选择。增加screen-batch原子写入，任一项失败全部回滚；版本变化时旧判断失效。
- 更新原automation真实提示及两份流程文档，保留原任务ID、专用会话、启用状态和3小时周期。已回读配置，旧“优先最新论文”指令已消除。
- 对原文URL与当前URL都明确指向同一arXiv固定版本的文档，允许复用已通过发布检查的报告；未带版本URL不推断等价，v1不能替代v2。没有改写原报告、文档哈希或用户状态，也没有放宽全文与证据门槛。候选登记会复用符合条件的已读报告，避免仅因元数据差异重复精读。
- 新增只读audit命令，报告未初筛量、待读等级、最早等待、最高优先级积压、批次剩余、发布阻断原因、过去24小时报告数、源状态及覆盖限制。已筛为0的候选不再错误显示“尚未评估”。
- 实际完成24篇公开标题与摘要的比较：3篇优先核查、14篇值得跟进、7篇常规。包含AIRoA-0、La-JEPA、RoboTryOn等待精读候选。这些判断没有冒充全文结论，未因此发布任何新论文，也未占用全文租约。记录见screening-pilot.json。
