# 展示前自动精读

用户明确：每篇进入前台展示的论文，都应先由GPT完成精读并产出有用的技术解读。用户的日常操作是理解新技术、选择是否深入，而不是给后台逐篇分派任务。

## 已实现的流程

采集论文 → 自动登记后台候选 → 分批比较公开摘要、逐篇记录重要性与范围 → 合格优先候选先行，普通候选完成整批初筛后领取 → 准备固定版本全文 → 完整文字精读与关键图表核查 → 生成方法、对照、实验证据、局限和技术增量卡片 → 引文、覆盖范围、来源版本与内容字段检查 → 自动进入前沿与日常论文列表。

前台先回答具体改动、比较对象、证据口径与研究意义，原文和完整精读报告按需展开。未精读、只有摘要、版本失效、引用不匹配或没有完整增量卡片的论文留在后台，不混入前沿。个人收藏和笔记保留；“稍后读”“已读”和用户自愿核查状态不承担发布前置条件。

独立模型API仍未配置，现有按需API实现保留。以后迁移托管后台时，可用服务端模型执行器消费同一队列，不改变用户的阅读流程。

## 展示检查与真实能力

- 固定来源版本与全文内容哈希；论文版本变化后旧结果退出当前展示，保留原始缓存、个人笔记和任务历史。
- 报告必须来自模型/会话代理，完整覆盖已提取文字，并包含有引文的方法与实验证据判断。正文提取覆盖不等同于读懂全部图表或公式；缺口显示在报告内。
- 每项重要判断带证据ID和原文逐字引文。技术增量卡片只压缩这些判断；引文存在不能证明语义正确，所有实验归作者，未复现。
- 报告与任务同事务提交。未通过展示检查时不发布，代理保留任务进行修正或释放后重试。
- 任务租约与令牌防止重复接手和取消后的迟到提交。原文准备失败最多尝试3次；代理超时可续租或恢复。
- 后台候选登记自动执行，不需要用户从前台点击“交给精读”。没有精读执行器时只等待，不批量下载无用原文或伪造解读。
